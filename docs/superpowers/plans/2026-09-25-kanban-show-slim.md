# kanban_show slim default Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `kanban_show`'s default response a slim, de-duplicated view (measured baseline 47,810 chars → 19,163 chars on card `t_b0a7c347`) while `full=true` returns today's payload byte-for-byte.

**Architecture:** Four pure, DB-free helper functions in `tools/kanban_tools.py` summarise runs, filter events and strip duplicated `worker_context` sections. `_handle_show` builds today's dict unchanged (so `full=true` is byte-identical by construction) and, when `full` is falsy, passes it through the helpers before serialising. `hermes_cli/kanban_db.py::build_worker_context` is **not touched** — the dispatcher's spawn-time context must stay exactly as it is.

**Tech Stack:** Python 3.11, stdlib `json`/`re`, pytest, `scripts/run_tests.sh` (per-file isolated runner).

## Design decisions (already made — do not re-open)

**D1 — `worker_context` keeps `## Body`; the slim `task` dict drops `body`.**
Reason: the card allows either, and explicitly prefers the variant that leaves `build_worker_context` untouched. Dropping `task["body"]` needs zero post-processing of the context string, so the spawn-time path is provably unaffected. It also keeps the body in the pre-formatted form the system prompt tells workers to "treat as ground truth". Cost: `_CTX_MAX_BODY_BYTES = 8192` caps the rendered body, so a body over 8 KB is truncated in slim mode — `full=true` still returns the untruncated `task["body"]`, and the `slim` block says so.

**D2 — parameter is `full`, boolean, default `false`,** declared in `KANBAN_SHOW_SCHEMA` and parsed with the existing `_parse_bool_arg(args, "full")` (which also accepts `"true"`/`"1"`/`"yes"` strings, like every other bool arg on this surface).

**D3 — the summarising lives in four module-level pure functions** in `tools/kanban_tools.py`, each taking plain `list[dict]` / `str` and returning plain data. No DB handle, no connection — unit-testable with literals. `_handle_show` stays a thin composition.

**D4 — "last finished run with summary" =** the newest run with `ended_at is not None` **and** a non-empty stripped `summary`, among the runs that survive the outcome filter. When none of them has a summary, fall back to the newest run with `ended_at is not None`. When there is no finished run at all, there is no anchor and `runs` is simply the (possibly empty) outcome-filtered tail. The anchor is *prepended* into the max-3 window, so it is never lost to the tail cut.

**D5 — event whitelist (literal, verified against the real board).** Distinct `task_events.kind` values on `hermes-dev` at plan time: `heartbeat` (10,598), `claimed`, `spawned`, `commented`, `respawn_guarded`, `created`, `completed`, `promoted`, `review_requested`, `dependency_wait`, `rate_limited`, `archived`, `blocked`, `unblocked`, `scheduled`, `changes_requested`, `assigned`, `linked`, `crashed`, `gave_up`, `timed_out`, `unlinked`, `reclaimed`, `attached`, `block_loop_detected`, `protocol_violation`, `archive_worker_termination`, `tip_scratch_workspace`, `suspected_hallucinated_references`, `note`, `decomposed`.
The card's words map to exactly these five:

```python
SLIM_EVENT_KINDS = ("blocked", "unblocked", "review_requested", "changes_requested", "completed")
```

`block` → `blocked`, `unblock` → `unblocked`, `review` → both `review_requested` and `changes_requested` (the two review-lane transitions), `complete` → `completed`. `heartbeat` is excluded by construction. Terminal-failure kinds (`crashed`, `gave_up`, `timed_out`) are **deliberately not** in the list — the card names four, not seven. `ANNAHME:` see A1.

**D6 — slim mode additionally strips the two `worker_context` sections whose data the payload already delivers structurally:** `## Prior attempts on this task` (duplicated by `runs`) and `## Comment thread` (duplicated by `comments`). This is the direct generalisation of the card's rule 3 ("either one or the other"), applied to the two other places the payload says the same thing twice; it is the single largest saving in the whole change (−8,746 chars). `## Parent task results` and `## Recent work by @<assignee>` are **kept** — neither is duplicated by a structured key.

**D7 — `_strip_context_sections` drops only the *last* occurrence of each heading.** Task bodies and comment bodies are rendered verbatim into the context and may themselves contain a line like `## Comment thread`. `build_worker_context` emits its sections in a fixed order (header/body → attachments → prior attempts → parent results → role history → comments), so the genuine section is always the last occurrence of its heading. Dropping only the last occurrence makes body-embedded lookalikes harmless.

@_kanban_handler("kanban_show")
def _handle_show(args: dict, **kw) -> str:
    """Task state. Trimmed by default (see ``_slim_show_payload``);
    ``full=true`` returns the complete state, byte-identical to what this
    tool returned before the trim existed."""
    tid = _require_task_id(args)
    full = _parse_bool_arg(args, "full")
    with _board(args.get("board")) as (kb, conn):
        task = _existing_task(kb, conn, tid)
        payload = {
            "task": _fields(task, _TASK_FIELDS),
            "parents": kb.parent_ids(conn, tid),
            # Non-terminal parents; on a running card this means the dependency
            # gate is not holding it and kanban_complete will refuse.
            "unsatisfied_parents": [
                {"id": pid, "status": status} for pid, status in kb.unsatisfied_parents(conn, tid)],
            "children": kb.child_ids(conn, tid),
            "comments": [_fields(c, _COMMENT_FIELDS) for c in kb.list_comments(conn, tid)],
            # Capped; full log via CLI.
            "events": [_fields(e, _EVENT_FIELDS) for e in kb.list_events(conn, tid)[-50:]],
            "runs": [_fields(r, _RUN_FIELDS) for r in kb.list_runs(conn, tid)],
            # Same string build_worker_context hands the dispatcher at spawn time.
            "worker_context": kb.build_worker_context(conn, tid)}
        if full:
            return json.dumps(payload)
        return json.dumps(_slim_show_payload(payload, len(kb.list_events(conn, tid))))

# --- kanban_show slim view ---

SLIM_MAX_RUNS = 3


def _slim_runs(runs: list[dict[str, Any]]) -> tuple[list[dict[str, Any]], Optional[str]]:
    """Trim a run history for the slim kanban_show view.

    Keeps the newest ``SLIM_MAX_RUNS`` runs that actually did something (an
    ``outcome`` that is neither ``None`` nor ``rate_limited``), always including
    the newest finished run that carries a handoff summary — that one is the
    single most useful row for a retry, and it is often older than the window.
    Rate-limited runs collapse into one count line: they burn a run row without
    producing anything, and a card can accumulate dozens of them."""
    rate_limited = [r for r in runs if r.get("outcome") == "rate_limited"]
    candidates = [r for r in runs if r.get("outcome") not in (None, "rate_limited")]
    finished = [r for r in candidates if r.get("ended_at") is not None]
    anchor = next((r for r in reversed(finished) if (r.get("summary") or "").strip()), None)
    if anchor is None and finished:
        anchor = finished[-1]
    kept = candidates[-SLIM_MAX_RUNS:]
    if anchor is not None and not any(r is anchor for r in kept):
        kept = ([anchor] + kept)[-SLIM_MAX_RUNS:]
    note = f"{len(rate_limited)} Laeufe rate_limited, 0 Calls" if rate_limited else None
    return kept, note
```

# Sections of the rendered worker context whose data the slim payload already
# delivers structurally: prior attempts == `runs`, comment thread == `comments`.
# `## Parent task results` and `## Recent work by @<assignee>` stay — neither has
# a structured counterpart, so dropping them would lose information, not repeat it.
SLIM_DROPPED_CONTEXT_SECTIONS = ("## Prior attempts on this task", "## Comment thread")

_CTX_HEADING_RE = re.compile(r"(?m)^(## .*)$")


def _strip_context_sections(text: str, headings: frozenset[str]) -> str:
    """Remove whole ``## <heading>`` blocks from a rendered worker context.

    Only the *last* occurrence of each heading is removed. Task and comment
    bodies are rendered verbatim and may contain a matching line; the genuine
    section is always emitted after them (build_worker_context's order is
    header/body -> attachments -> prior attempts -> parent results -> role
    history -> comments), so the last match is the real one."""
    parts = _CTX_HEADING_RE.split(text)
    last: dict[str, int] = {}
    for i in range(1, len(parts), 2):
        if parts[i].strip() in headings:
            last[parts[i].strip()] = i
    drop = set(last.values())
    out = [parts[0]]
    for i in range(1, len(parts), 2):
        if i not in drop:
            out.extend([parts[i], parts[i + 1]])
    return "".join(out)
```

    """Trim a full kanban_show payload for the default (slim) response.

    Pure: takes and returns plain data, so every rule is unit-testable without

    comments live in ``comments`` only."""
