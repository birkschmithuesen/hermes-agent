## 1. Finding (measured 2026-11-18, architekt)

Chain of the failure (cothinker/t_6c6b16fb run 3233, `task_runs.error` =
`kanban_skills_unavailable: sdlc-review unavailable for profile 'coder' (disabled or unknown there)`):

1. The coder called `kanban_request_review` **without** `reviewer=`. `request_review`
   (`hermes_cli/kanban_db.py`, `def request_review`) only rewrites `assignee` when `reviewer`
   is set (`assignee_sql = ", assignee = ?" if reviewer is not None else ""`), so the card stays on `coder`.
2. The dispatcher's review lane force-loads `sdlc-review` for every review spawn
   (`hermes_cli/kanban_db_dispatch.py`, comment "Force-load sdlc-review", origin/main line 2147-2149;
   birk-local 2321-2323). The managed worker does the same (`gateway/session_kanban.py:47-48`).
3. `profiles/coder/config.yaml` lists `sdlc-review` under `skills.disabled` (generated by
   `scripts/fabrik-skill-pool.py` from `scripts/fabrik-skill-pool.yaml`, birk profile repo).
   `build_preloaded_skills_prompt` counts disabled skills as missing -> `kanban_skills_unavailable`.

## 2. Decision: variant (b), fail early at handoff

The card offers (a) silent reassignment to a default reviewer profile, or (b) an early, clear refusal.
**Chosen: (b).**

- (b) fits the existing contract: `request_review` already refuses with a reason and leaves the task
  untouched (`parent dependencies are not satisfied`, `re-review has no durable reviewer provenance ...;
  pass reviewer= explicitly`), and the tool layer already refuses an unknown reviewer (#106163) and
  pre-created children. The model sees `tool_error` and retries with `reviewer=`.
- (a) would need a new config key (which profile is "the" reviewer; this host has `reviewer`,
  `reviewer-dgx`, `reviewer-dgx-think`) and would silently pick a reviewer for every board, including
  boards whose review is done by a different profile. That is a policy choice the kernel should not make.
- `sdlc-review` stays disabled for coder (card constraint: the implementer must not review its own work).

Single source of truth: the review lane's forced skill. The plan adds the constant `REVIEW_LANE_SKILL`
next to `request_review`. It deliberately does NOT rewrite the two existing literals (dispatcher, session_kanban)
to keep the diff to one file (S). ANNAHME for a follow-up: pointing those literals at the constant is a
pure refactor and not needed for the fix.

Scope boundaries:
- The check reads only `skills.disabled` of the profile that will run the review (`reviewer` if given,
  else the current assignee). It does NOT check that the skill exists on disk: the dispatcher's own
  `_check_skills_available_for_assignee` (feat `kanban-forced-skill-unavailable`) treats unknown skills as
  missing, but test fixtures across `tests/hermes_cli/test_kanban_review_*.py` create review profiles with
  an empty `config.yaml` and no skills dir. An existence check broke 4 of them in the replay (see §5).
  The real failure mode on this host is `disabled`, which this check covers.
- Skipped when `kanban.review_dispatch` is false (human-only review boards spawn no review worker).
- Fails open for unknown profiles (same rule as the unknown-reviewer guard and the create-time skill guard).
- Platform-scoped `skills.platform_disabled` uses the caller's platform, not the review worker's
  (`get_disabled_skill_names` reads `HERMES_PLATFORM`). ANNAHME: no profile on this host uses
  `platform_disabled` for `sdlc-review` (check: `grep -n platform_disabled ~/.hermes/profiles/*/config.yaml`).

Standard tools: pytest via `scripts/run_tests.sh` (the repo's runner), existing fixtures pattern
(`HERMES_HOME` + `Path.home` monkeypatch, as in `tests/hermes_cli/test_kanban_create_skills_guard.py`
on feat `kanban-forced-skill-unavailable`). No custom infrastructure.

**Files**
- Modify: `hermes_cli/kanban_db.py` (new constant + helper directly above `def request_review`, 3-line call
  inside `request_review` right after `reviewer = _canonical_assignee(reviewer)`).

**Interface**
- `REVIEW_LANE_SKILL = "sdlc-review"` (module constant).
- `_review_skill_refusal(review_profile: Optional[str]) -> Optional[str]`: reason text or `None`.
- `request_review(...)` returns `(False, <reason>)` with `with_reason=True` (else `False`) and changes
  nothing (no status, assignee, run or event change) when the review profile disables `sdlc-review`.
  The reason contains `sdlc-review`, the profile name in `repr` form and the literal `reviewer=`.
- No change in `tools/kanban_tools.py`: `_handle_request_review` already turns `(False, reason)` into
  `tool_error("could not request review for <tid>: <reason>")`. The CLI (`hermes kanban request-review`)
  and the dashboard (`plugin_api.py` status `review`) get the same refusal for free.

### Step 3: implement

In `hermes_cli/kanban_db.py`, insert directly above `def request_review(`:

```python
REVIEW_LANE_SKILL = "sdlc-review"


def _review_skill_refusal(review_profile: Optional[str]) -> Optional[str]:
    """Reason to refuse a review handoff whose review-lane worker would die at spawn, else None.

    The dispatcher force-loads ``sdlc-review`` for every review-lane spawn under the task's
    assignee after the handoff (``reviewer`` if given, else the implementer). A profile whose
    config disables it fails deterministically with ``kanban_skills_unavailable``. Skipped
    when review dispatch is off (human-only review boards spawn nobody); fails open for
    unknown profiles."""
    from hermes_cli import kanban_db_dispatch as _kbd
    if not review_profile or not _kbd.review_dispatch_enabled():
        return None
    from hermes_cli.profiles import get_profile_dir, profile_exists
    if not profile_exists(review_profile):
        return None
    from agent.skill_commands import _disabled_skill_names
    from hermes_constants import reset_hermes_home_override, set_hermes_home_override
    token = set_hermes_home_override(str(get_profile_dir(review_profile)))
    try:
        disabled = _disabled_skill_names()
    finally:
        reset_hermes_home_override(token)
    if REVIEW_LANE_SKILL in disabled:
        return (
            f"the review lane would run as {review_profile!r}, which disables {REVIEW_LANE_SKILL} "
            "(skills.disabled in that profile's config), so the review worker would die at spawn; "
            f"pass reviewer=<profile> naming a review profile that loads {REVIEW_LANE_SKILL}"
        )
    return None
```
